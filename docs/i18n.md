# Texts and languages

- `src/i18n/ru.ts` — the Russian texts, the source. `en.ts`, `he.ts` — translations, filled as they come.
- `t('nav.resorts')` (plain functions) or `const t = useT()` (components) returns the text in the
  page's language, Russian when a translation is missing. Keys are typed: a wrong key fails the build.
- Variables: `t('steps.step', { n: 2 })` with `«Шаг {n}»` in the dictionary.
- The language switch in the phone menu shows only when a second language is **complete**
  (`completeLanguages()` in `src/i18n/t.ts`) — a switch that changes nothing misleads.
- Hebrew is right-to-left: `usePageLanguage` sets `<html dir="rtl">`. New CSS uses logical
  properties (`margin-inline-start`, `padding-inline`, `inset-inline-end`) where the side matters.

## Moving a page's texts

Done: header and menu, steps bar, step guards, loading/error blocks, the order page.
Next, page by page (largest first): Results, Hotel, Transfer, Rooms, Guests, Payment, Done, Tickets, Main, Rules.

1. Add a group to `ru.ts` named after the page (`results: { … }`).
2. Replace each text in the JSX with `t('results.…')`; texts built from numbers get `{n}` variables.
3. Pages declare the languages they are complete in: `static languages = ['ru', 'en']` on the page logic.
4. `npm run build` — a key missing from `ru.ts` is a type error.
